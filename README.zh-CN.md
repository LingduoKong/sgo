# SGO 中文说明：面向外贸企业负责人

[English README](README.md)

## 实现原理摘要

**SGO 通过多次调用现有 AI 模型，模拟不同客户对同一份业务材料的评价，再比较修改前后的预计分数，给出改进优先级。**

具体分为四步：

1. **准备人物**：根据目标受众，从本地人物数据中筛选、抽样，或让 AI 生成人物背景。
2. **分别评价**：把每个人物的背景与同一份开发信、产品介绍或报价说明交给模型，分别得到评分、吸引点和顾虑，再汇总结果。
3. **测试修改**：围绕评分 4—7 分、仍在犹豫的人提出候选修改，让模型结合原评价估计修改后的分数。
4. **排序建议**：计算预计分数变化；有明确目标时，结合人物与目标的相关程度加权，排出值得优先验证的修改。

人物和反馈都是模拟的，建议需要用真实客户验证。系统不会自动寻找采购商或发送邮件。

## 工作原理：用一个外贸案例看懂

假设你的公司出口保温杯，准备向法国礼品进口商发送下面的介绍：

> 我们供应不锈钢保温杯，支持定制标志。500 件起订，常规款样品 7 天内寄出，大货交期约 30 天。欢迎告知所需数量和定制要求。

你想知道：这段话能不能让合适的买家愿意进一步沟通？下面的条件和分数均为虚构示例，不是实际测试结论。

### 1. 告诉系统：看什么、为了什么、问谁

| 输入 | 示例 |
| --- | --- |
| 客户会看到的材料 | 实际开发信，以及产品规格、定制、样品和交期说明 |
| 本次目标 | 让符合条件的进口商回复采购需求，进一步讨论样品 |
| 目标买家 | 法国中小型礼品进口商的采购负责人，重视批次质量和交货稳定性 |

目标越具体越有用。首次开发信的目标可以是“获得有效回复”，不必把每个沟通阶段都设成“立即下单”。合作条件也要写准确，例如起订量究竟是每款、每色，还是可以混色。

### 2. 组成一组虚拟评审

界面中的 **Panel** 是“评审小组”。人物有两种来源：

- **国家数据集**：从根据人口统计等信息生成的人物资料中筛选、抽样，资料包含年龄、职业、地区和生活背景。
- **LLM-generated personas**：让 AI 按你描述的受众现场生成人物，更灵活，但也更容易重复或遗漏某类人。

#### 本地人物数据从哪里来？

目前接入的是 **NVIDIA 发布的 Nemotron-Personas 系列**，通过 Hugging Face（公开的 AI 模型与数据平台）下载到本机。“本地”指保存位置，不是企业自己收集的客户资料。

它的制作思路是：**参考公开人口统计，构建人物背景分布，再用 AI 补充职业经历、兴趣和生活描述，形成虚拟人物资料。** 例如，美国版参考美国人口普查局的“美国社区调查”，印度版参考 2011 年人口普查；具体来源与限制见各国官方说明。

当前六个国家的官方出处：[美国](https://huggingface.co/datasets/nvidia/Nemotron-Personas-USA)、[日本](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Japan)、[印度](https://huggingface.co/datasets/nvidia/Nemotron-Personas-India)（本项目使用英文版）、[新加坡](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Singapore)、[巴西](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Brazil)、[法国](https://huggingface.co/datasets/nvidia/Nemotron-Personas-France)。

**人口统计提供的是背景参考，不是真实购买意愿。** 数据里的每条记录是合成人物，而本次材料的评分和反馈由 SGO 调用模型另行生成；它们不是这些人物接受过的真实访谈。

**选“法国数据”，不等于选到了法国采购商。** 这些资料不是进口商名录，也不是可联系的买家名单。普通居民喜欢一只杯子，与进口商是否愿意批量采购，是两回事。

针对专业采购场景，可以选择现场生成人物，并写清国家、公司类型、岗位、采购规模和关注点。例如，采购人员关注交期，品控人员关注一致性，企业负责人关注资金占用。先检查人物背景是否贴近你的客户，再看评分。

### 3. 让 AI 分别评价同一份材料

系统把材料与人物背景一起交给 AI，让它分别给出 **1—10 分的评分、认可程度、吸引点、顾虑及理由**。

比如，有人可能问：“500 件起订是每种颜色都要达到吗？”另一个人更关心：“大货与样品的质量如何保持一致？”

这些角色通常由同一个 AI 模型分别扮演，不是真人，也不会还原一家企业内部共同审批订单的全过程。

### 4. 重点分析仍在犹豫的人

系统按评分大致分为：**8—10 分比较认可，4—7 分仍在犹豫，1—3 分当前不太匹配**。比较修改方案时，重点关注 4—7 分的人。

原因很直观：不经营礼品的买家，未必会被降价打动；正在找保温杯供应商、只是没看懂定制条件的人，可能更值得争取。低分意见仍可用来检查产品问题或受众是否选错。

### 5. 估计修改后的变化，排出优先级

系统根据顾虑提出候选修改，再让 AI 结合原有角色和评价，估计新分数。例如，写清起订规则后，一位虚拟买家的分数从 5 分变成 7 分，预计影响就是 **+2 分**。

系统汇总这些变化，并尝试给与目标更相关的人物更高的参考权重，生成修改排名。“语义梯度优化”就是寻找这种**可能让目标受众更愿意接受的修改方向**，使用时不需要懂数学公式。

## 怎么操作？

服务启动后，打开提供给你的网页地址。本机通常是 [http://127.0.0.1:8000](http://127.0.0.1:8000)，它只对运行服务的那台电脑有效。

| 页面内容 | 你需要做什么 |
| --- | --- |
| **What should the panel review?** | 粘贴实际准备给客户看的文字。发英文开发信，就放英文原文；不会 Markdown 排版也能用 |
| **Edit / Preview** | 编辑原文／查看排版，切换不会改变内容 |
| **What outcome are you optimizing for?** | 写明本次目标，例如获得有效回复或讨论样品 |
| **Who should be on the panel?** | 写明买家类型。可用中文；Auto-fill 能帮忙起草，但需要自己核对 |
| **Dataset / Panel size** | 选择人物来源和人数。人数默认 30；人数增加通常意味着更多时间和费用 |
| **Build panel and review** | 开始评估，等待结果 |
| **Full analysis** | 查看详细分析；Rendered 显示排版，Source 显示原文 |
| **Test what to change next** | 比较候选修改 |
| **Download report** | 保存报告，方便团队讨论 |

当前网页主要评估粘贴的文字，不会自动读取邮箱、客户网站、附件或产品实物。界面和部分报告标题仍是英文。

### 数据状态怎么看？

目前提供美国、日本、印度（英文版）、新加坡、巴西、法国六个国家选项，也可以现场生成人物。目标市场没有对应选项时，不要直接把别国普通居民当作目标采购商。

- **ready**：本地已有可识别的数据，评估时会自动读取，不必重复下载。
- **needs loading**：尚未找到可用数据；可能没下载，也可能保存在未识别的位置。
- **Load selected dataset**：准备所选数据；没有可用本地副本时会尝试下载。
- 已下载到其他目录的，可以在 **Advanced** 中指定位置，或请安装人员处理。

现场生成人物不需要下载国家数据，但会调用 AI 服务。

## 如何把结果变成有用的判断？

**先看反复出现的理由，再看平均分。** 对照业务员实际收到的询盘、议价和拒绝理由，判断 AI 提出的问题是否值得验证。

下面仍是保温杯出口的虚构示例：

| 假设修改 | 模拟平均加分 | 企业负责人需要核对什么 |
| --- | --- | --- |
| 写清定制和起订规则 | +1.2 | 是否符合工厂实际条件？客户是否经常追问？ |
| 补充大货质量控制说明 | +0.8 | 有没有真实流程和资料支持？ |
| 降低单价 | +0.3 | 可能的收益是否值得损失利润？ |

解读时记住三点：

1. **分数不是成交率。** 平均 6 分不等于六成买家会回复；+1.2 分不等于销量增长 12%。页面里的认可、犹豫和不认可，也不是订单数。
2. **修改效果不能简单相加。** 两项建议各加 1 分，合起来未必加 2 分；还要看成本、对其他买家的影响，以及能否兑现。
3. **评分不能核验事实。** 产品参数、资质、交期和交易条件仍需人工确认，不能为了高分而加入不真实的承诺。

两个可选功能，首次使用可以跳过：

- **Know the current performance?**：填入真实点击率、有效询盘率等，把评分变化换算成粗略参考。要区分“访问者产生询盘”和“邮件收到回复”等不同口径；换算结果不证明实际业绩会增长。
- **Check panel realism**：改变说法、可信度提示或材料顺序，观察评价是否过度变化。它是模型检查，不是预测准确性的认证。

## 企业负责人如何安排团队使用？

1. **限定场景**：一次只选一个市场、一类买家和一个沟通阶段。
2. **准备并评估材料**：业务员提供实际文案，核对人物背景，整理主要顾虑。
3. **核实后修改一个重点**：由业务、生产或品控确认，不要同时更改价格、交期和付款条件。
4. **用真实客户验证**：在正常沟通中小范围尝试，记录有效回复、询价或样品申请，同时留意线索来源、发送时间和跟进方式的差异。

每次留下一份简表即可：**原文、目标买家、主要顾虑、最终修改、真实反馈**。

网页重新评估会重新建立小组，分数变化也可能来自人物选择和 AI 回答的波动。需要固定同一组人物比较时，请技术人员使用脚本保存并复用人物资料。

## 使用前确认三件事

- **费用**：项目开源，但连接的 AI 服务可能收费。耗时和费用取决于模型、材料长度、人数及测试次数。
- **资料去向**：评审材料和人物背景会发送给配置的 AI 服务商；网页在本机打开，不等于全部计算都在本机完成。不要放入不希望交给该服务商的客户名单、底价表或未公开图纸。
- **结果保存**：网页结果主要保存在服务的临时内存中。重要报告先下载，刷新页面或重启服务后不保证自动恢复。

日常操作不需要写代码。请协助人员安装环境、配置 AI 服务、准备人物数据并提供访问地址。
